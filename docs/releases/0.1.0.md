## Local coding workspace

Connected paths remain local. Models receive folder IDs/names and can call on-demand list/read/search, edit/write/move/delete and local command tools. Folders are not copied into the app cache. Historical attached context remains available for cleanup and existing message provenance; it is not added to new requests.

File tools support UTF-8 regular files up to 256 KB. Changes to existing files require fresh hashes and save original bytes/permissions in `file-edit-backups` under app data. Create needs an existing parent; directory operations use terminal tools. Edits use pinned handles and recovery copies rather than atomic replacement. Concurrent external filesystem changes are not an isolation boundary. Folder tools exclude credentials and Git internals; shell has ordinary local process permissions and can access beyond the selected directory.

Terminal jobs default to 60 seconds, support up to 300 seconds, allow two running commands and cap output at 256 KiB. Stop terminates the process group. Durable invocation identities prevent automatic replay; old output expires while the identity remains. Normal server exit attempts cleanup. An abrupt OS crash can leave detached descendants; restart reports interrupted jobs and does not blindly rerun or kill reused process IDs.

Workspace ZIP backups include saved workspace and owned assets. They do not back up connected repositories or local edit/command recovery directories. Keep repositories in Git and maintain their own backups. Recovery originals remain manually accessible in app data.
