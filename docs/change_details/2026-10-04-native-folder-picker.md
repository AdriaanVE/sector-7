# Native folder picker

Sector 7 opened folder selection by spawning AppleScript, activating the script process and invoking the legacy chooser. A macOS stack sample showed `WaitToComeToFront` and deprecated panel code before selection. The observed path justifies removing the detour; it does not account for the entire reported 20-second delay.

Electron now opens a native directory sheet attached to its trusted main window. The browser launcher compiles and ad-hoc signs a small AppKit helper at startup, reusing it until source or bundle metadata changes. Both paths validate the chosen absolute directory on the server and leave connections in the project draft until Save. The browser helper is separate from the Electron package.

The manual `Build Mac app` workflow runs only on `main`, checks web/desktop code, builds the Apple silicon app/DMG and uploads downloadable artifacts for 14 days. It does not publish releases. App archives use `ditto` to preserve bundle permissions. A fresh staging directory avoids retained macOS ACLs in earlier build output; `SECTOR7_DESKTOP_OUTPUT` selects a separate output directory when needed.

The user approved three test seams: folder-selection API, desktop picker bridge and live native chooser. Red/green regressions reject non-string selected paths and discard browser results after editor cancellation. Existing native tests preserve canonical paths, whitespace, cancellation, timeout and duplicate gates. Desktop tests verify window/main-frame/origin authorization, duplicate gates, failure recovery and discarded results after navigation.

The AppKit helper compiled and passed strict signature verification. Its real chooser displayed; Cancel returned exit code 2, and selecting an empty temporary folder returned the expected canonical connected-folder object through the server picker interface. The first compile took about 1.3 seconds and cached preparation about 2 milliseconds. These are preparation measurements, not click-to-popup latency.

Independent Claude review identified a checksum file placed in `Contents/MacOS`; a real package signing failure confirmed it. The browser checksum now lives outside the bundle, and the unused helper was removed from the desktop package. The corrected source review approved the changes with no blocking defects. The standalone copy excludes generated browser helper output. A fresh helper launch and visible-dialog observation took about 3.1 seconds including automation overhead; this is not a controlled click-to-popup benchmark. Unpackaged Electron supports `SECTOR7_DESKTOP_STAGE` for a retained staged server. Hosted workflow execution and installed-app click-to-popup timing remain separate acceptance checks.

The desktop branch was rebased onto freshly fetched `origin/main` at `6e02446227f85887c54de7f1ea47167043b6c91e`. Both main's default-tool regression and the desktop environment regression were retained. After rebase the quality gate passed 213 tests with 22 network skips, types and lint; desktop types and six tests passed. The production app and DMG built successfully in `/private/tmp/sector7-rebased-readme-app`, including strict signature verification. The README was rewritten for both launch paths, manual GitHub builds, credentials, tools, storage and preview limits. `docs/sector-7.png` is a real saved app preview using generic test content; its format, dimensions and README link were verified.

The final independent Claude integration/documentation review approved the frozen snapshot with no blocking defects and no permission denials. Its output-path finding was fixed: relative `SECTOR7_DESKTOP_OUTPUT` values now fail immediately with a clear error, before a build starts. Direct execution verified that rejection; syntax and desktop type checks passed afterward. The documented source-launch stage setting remains required. README and desktop setup now explain that packaging rebuilds the shared production web output. The manual hosted build remains unverified until the workflow is available on `main`.
