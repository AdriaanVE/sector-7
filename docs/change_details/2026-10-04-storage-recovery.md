# Storage recovery and resource bounds

Stale workspace saves now pause editing and new requests. A recovery dialog retains the live tab and offers a manual JSON copy of unsaved records and their referenced originals, or an explicit reload of the saved workspace. Missing disk assets fall back to disposable browser originals. Reload waits for active work to settle; downloading remains available. Temporary errors retain Retry. Last saved advances only after acknowledgement.

Local request bodies count streamed bytes before whole-body allocation. Workspace save and backup/restore retain a 250 MiB bound; small tool requests use 2 MiB. Assets stream on GET and remain compatible with legitimate legacy attachments above 10 MiB. ZIP validation limits entries to 10,000, checks actual decompression bounds, checksum and record identity, and rejects unexpected or duplicate paths. Stored ZIP export accounts for headers so every successful export fits the import bound.
